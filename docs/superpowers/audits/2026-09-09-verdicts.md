# Adversarial review verdicts — 2026-09-09

Six agents reviewed the source in parallel, one dimension each, briefed to
argue the code is broken. This is what survived trying to disprove it.

**8 behavioural claims tested. 7 reproduced, 1 disproved.** Several structural
claims were settled by inspection rather than by test, and are marked as such.

## Reproduced and fixed

Each had a test that failed on the code as it stood, on all three engines,
before any fix. The tests are in
`packages/detent/test/browser/audit-claims.test.ts`.

| # | Claim | Evidence |
| --- | --- | --- |
| 1 | A refused `onStart` leaves `detent-dragging` stuck on the element | `expected true to be false` — class present after a refused start |
| 2 | Same for `detent-resizing` | as above |
| 3 | `session.cancel()` inside `onStart` locks the page permanently | `pageLockDepth()` was 1 with no drag running |
| 4 | `handle.destroy()` inside `onStart` does the same | `pageLockDepth()` was 1 |
| 5 | Keyboard reordering fires only `onSort` | `onStart` and `onEnd` called 0 times |
| 6 | A two-item horizontal list cannot be reordered | order unchanged: `['0','1']` |
| 7 | A cross-list drop reports the index with the *source* list's `items` selector | index counted over the wrong subset |

Claims 1–4 share one root cause: `onStart` can re-enter the pointer layer, and
`activate()` did not re-check that the session survived the callback.

## Disproved

| # | Claim | Why it is wrong |
| --- | --- | --- |
| 8 | Removing the dragged item from the DOM mid-drag throws on `pointerup` and skips teardown | Claimed independently by **two** agents, with a plausible read of `dragged.parentElement as HTMLElement`. A test that removes the item mid-drag and releases the pointer **passes**: no throw, `onEnd` fires, teardown runs. The cast is still worth removing for clarity, and claim 7's fix does so, but the failure described does not occur. |

This is the reason the disproof pass exists. Two independent reviewers reading
the same line reached the same confident, wrong conclusion.

## Settled by inspection

| Claim | Verdict | Evidence |
| --- | --- | --- |
| `__DEV__` invariants are inert in every consumer environment | **CONFIRMED** | Every `build.mjs` sets `__DEV__: 'false'`; there is no dev build and no `development` export condition. `dist/index.js` contains zero `throw new Error`. Phase 1 verified that dead-code elimination *worked* and never asked whether the guards fire for anyone. They do not. **Not yet fixed** — see below. |
| `sortable` has no `setDisabled`, so `disabled` is dead after bind | **CONFIRMED** | `grep setDisabled packages/detent/src/sortable/index.ts` → no match, while `draggable` and `resizable` both expose it. **Not yet fixed.** |
| `<detent-resizable aspect-ratio>` (valueless) yields `aspectRatio: 0` | **CONFIRMED** | `Number('') === 0` and `Number.isFinite(0)` is true, so `num()` returns `0` and the `?? this.bool(...)` fallback is dead for exactly the input it was written for. Same hole for `animation` and `distance`. **Not yet fixed.** |
| `disabled="disabled"` leaves the element enabled | **CONFIRMED** | `bool()` returns `undefined` for any value but `''`, `'true'`, `'false'`, and `undefined` means enabled. The canonical HTML boolean spelling is the failure case. **Not yet fixed.** |
| `--detent-handle-size` cannot be set from an ancestor | **CONFIRMED** | Declared on `.detent-handle` itself, and a declaration on the element beats an inherited value regardless of specificity or layer. The documented theming knob does not work the way anyone would try to use it. **Not yet fixed.** |
| "Inline styles are beyond the reach of any host stylesheet" is false | **CONFIRMED** | An author `!important` declaration beats a non-important inline one. `* { position: static !important }` is a standard print reset. The comment overstates the guarantee. **Documentation fix pending.** |

## Judgement calls, not defects

- **`box-sizing: border-box` is load-bearing but sits in the overridable
  layer.** The reasoning is sound and the failure mode is real, but the fix is
  a behaviour change to sizing that deserves its own change and its own test,
  not a drive-by.
- **`sortable/index.ts` should split at the host-resolution seam.** The agent
  named the seam precisely and the argument holds. It is a refactor with no
  behavioural claim attached, so it is not an audit finding.
- **FLIP's second loop interleaves reads and writes.** Correct as described.
  Whether it matters at realistic list sizes is unmeasured, and optimising on
  an unmeasured claim is how you make code worse. Needs a benchmark first.
- **React hooks hand-enumerate option keys with no parity check.** True, and
  the Svelte proxy proves a generic forwarder is possible. A missing key is a
  silent no-op. Worth a follow-up.

## Still open

The confirmed-but-unfixed items above are real and should be addressed. They
are listed here rather than fixed in the same change because each is a
behaviour change to a published API and belongs in its own reviewed commit.
The highest-value one is the dev build: **every invariant in the library is
currently unreachable code for every consumer**, which makes the entire
error-handling policy a comment.
